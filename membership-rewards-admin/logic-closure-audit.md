# 运营中心逻辑检查说明

2026-11-22检查范围为当前五个页面、编辑与运营操作、数据保存、旧数据迁移和权限。功能及运行方式以[README](README.md)为准；字段、操作、验收和用例见[完整开发与测试说明](docs/原型开发与测试说明.md)，编号清单见[需求列表](docs/需求列表.md)。

原型内已验证独立保存、会员关闭及恢复／失效、优惠券类型锁定和逐券规则、邀请去重与旧轮次、奖励独立发放及原单重试、核验和撤券。103项业务测试覆盖上述规则及存储失败、旧标签冲突和损坏数据保护；另4项检查说明规范及同源文件一致性。文档的96个用例为验收基线，不能替代真实服务联调结果。

## 当前接入边界

- 后台、需求发布与个人中心各自维护演示数据，未共享配置、会员状态、优惠券资产或活动结果。用户端仍有固定价格和邀请奖励参数，不能把后台保存成功理解为用户端已生效。
- 需求支付仅配置开关与金额，未创建真实需求单／支付单或接收支付回调。免费、会员免费、抵用后零元、付款成功发布及失败恢复尚未形成服务链路。
- `orderDiscount()`用于验证逐券抵扣规则，不检查持有人、有效期或订单绑定，也不执行占用、核销和退券。真实服务还需保证并发使用同券及重复回调不造成重复扣券。
- 退款方式及补偿天数目前只保存为配置和快照，没有真实全额／部分退款执行；未配置的退款规则继续显示待配置。
- 邀请和奖励处理经过模型测试，未接收真实注册事件。需要唯一实际用户标识、唯一邀请归属、可靠事件投递、发放幂等键和库存／限额事务。账号冻结单据保留人工处理，当前后台不负责解冻账号。
- 操作日志在本地保留；生产审计、对账、跨设备同步和权限需要实际服务支持。本地存储令牌比较不能替代服务端版本控制或数据库事务。

## 接入前仍需明确

| 问题 | 已明确的范围 | 尚需明确的部分 |
| --- | --- | --- |
| 优惠券组合 | 同模板多张累计门槛 | 不同模板叠加、金额券与抵用券混用及抵扣顺序 |
| 支付场景 | 金额券三类支付范围；抵用券需求发布／接单支付 | 实际费用项与接口枚举的对应，避免误合并发布费与课程费用 |
| 配置变化 | 后台各项保存后立即生效 | 待支付单遇调价、开关或会员状态变化时的报价及锁券处理 |
| 退款与补偿 | 每券配置全额退款退券方式 | 部分退款分摊、补偿起算及已失效会员的购买退款流程 |
| 自定义会员权益 | 展示信息、图标、启停，最多5项 | 每项实际服务能力与鉴权入口 |

清理无入口代码不会补齐以上服务链路，也不会改写已有用户数据或历史快照。
